# LingKuma → Anki 使用手册

## 使用前准备

1. 安装并启动 Anki。
2. 在 Anki 中安装 AnkiConnect，并保持本机接口可访问。默认地址是 `http://127.0.0.1:8765/`。
3. 先在 Anki 中创建目标牌组。LingKuma 不会替你创建、删除或切换牌组。
4. 配置至少一个 LingKuma 语境释义提供方。发音音频是可选项。

LingKuma 只访问精确的本机 loopback AnkiConnect 地址，不连接远程 AnkiConnect。

## 一次性设置

打开扩展设置，进入“Anki 摘录”：

1. 填写 AnkiConnect 地址；仅在 AnkiConnect 本身设置了 key 时填写 API Key。
2. 点击“测试连接”。
3. 选择目标牌组，填写学习语言和释义语言。
4. 按需开启“自动附加可用的发音音频”。
5. 点击“保存并启用”。

保存时会创建或核对专用笔记类型 `LingKuma Lookup v1`。它固定包含以下字段：

`CaptureId, Language, Term, Reading, Meaning, Context, SentenceTranslation, Usage, UserNote, Source, CapturedAt, Audio`

已有兼容类型会被复用；LingKuma 不会在普通写入时覆盖你修改过的模板或 CSS。字段缺失、顺序变化或目标牌组不存在时，相关写入会停止并显示错误，不会删除后重建笔记。

未完成设置前主动查词仍会先保存到本地。设置完成后，待处理记录会自动继续，不需要逐条重查或点保存。

## 日常使用

完成设置后，不需要额外的逐词保存操作：

- 主动点击单词并打开查词结果，会立即在本地保存该语境；有效释义完成后自动写入本机 Anki。
- 选中短语并完成现有查询手势，只保存最终确认的选区；拖动中的中间选区不会保存。
- LingKuma 已有的网页、EPUB、PDF 和字幕查询入口使用同一流程，并尽量保留章节、页码或时间点。
- 主动查询已知词仍可保存。悬浮、预览、播放发音、关闭弹窗、重绘、打开历史或改变词汇状态不会创建摘录。
- 关闭弹窗或标签页不会取消已经落盘的工作。

同一语境再次查询会打开同一条摘录，不重复调用同一代释义任务，也不重复创建 Anki 笔记。同一个词换到另一句真实语境，会得到独立摘录和独立笔记。

## 状态说明

| 状态 | 含义 | 需要做什么 |
|---|---|---|
| 本地已保存 / 等待释义 | 原始词、语境和来源已落盘，释义尚未完成 | 通常无需操作；失败会有限重试 |
| 等待设置 | 本地记录存在，但尚未完成 Anki 设置 | 完成一次性设置 |
| 等待 Anki | 内容已准备，Anki 当前不可达 | 启动 Anki；队列会自动恢复 |
| 已同步 | 已读回并核实写入本机 Anki | 无 |
| 需要处理 | 本地和 Anki 均有变化，或同一 CaptureId 匹配多条笔记 | 在管理页比较后选择保留 Anki、本地或逐字段处理 |
| Anki 笔记不存在 | 已关联笔记被删除 | 显式重建，或停止管理；不会偷偷补建 |
| 已阻止 | key、profile、牌组或笔记类型配置不再兼容 | 修复设置后重试 |
| 已停止管理 | 保留历史，但不再自动写入 | 需要时显式恢复管理 |

状态“已同步”只表示已写入并核实**本机 Anki**，不表示已经同步到 AnkiWeb、手机或另一台电脑。

## 音频

开启音频后，仅可导出真实音频字节的已配置渠道会参与。浏览器 `speechSynthesis` 或 `chrome.tts` 只能播放，不能假装成可持久化音频。

文字笔记总是先写入。音频下载或上传失败只影响音频状态；恢复后更新同一笔记的 `Audio` 字段，不新建笔记。Anki 卡片引用内容哈希文件名，不依赖浏览器临时 blob URL。

## 管理、异常和外部修改

在设置页点击“管理摘录”可以：

- 搜索、按状态筛选和按词查看语境；
- 编辑释义、读音、原句翻译、用法和个人笔记；
- 核对 Anki、打开关联笔记、重试失败任务；
- 处理本地与 Anki 的字段差异；
- 对缺失笔记执行显式重建；
- 停止或恢复管理某条语境。

LingKuma 编辑会原地更新原笔记，不删除重建，也不修改牌组调度、卡片复习字段或用户额外标签。Anki 中的外部编辑会在打开/编辑时或低频本地巡检中被发现；两边都改过时不会静默覆盖。

“停止管理”不会删除本地历史或 Anki 笔记。再次查询仍显示原记录，只有“恢复管理”才重新启动写入。

## 备份与恢复

管理页可以导出版本化 JSON，并导入之前的本地备份。备份包含摘录内容和最小关联基线；不包含 AnkiConnect key、活动 lease、临时 requestId、noteId 提示或可重放的未确认写入。

恢复规则：

- 已有较新本地内容不会被旧备份覆盖；
- 恢复的关联先重新核对 Anki，不信任旧 noteId；
- Anki 中已删除的笔记不会因旧备份自动复活；
- schema、大小、CaptureId 或媒体完整性校验失败时，导入在写事务前拒绝。

备份只保护 LingKuma 本地摘录，不替代 Anki collection 备份或 AnkiWeb 同步。

## 多设备边界

Anki 负责 AnkiWeb、跨设备同步、合并和复习算法。LingKuma 不调用 `sync` 或 `loadProfile`，不远程连接另一台 Anki，也不复制浏览器任务队列。

如果 Anki 已先把同一 CaptureId 同步到另一台电脑，LingKuma 会关联已有笔记。两台尚未同步的 Anki 仍可能各自创建同一记录；后来出现多条同 ID 笔记时，LingKuma 会停止自动更新并提示处理。普通 AnkiConnect 读写不是数据库 CAS，不能承诺两台并发编辑的全局恰好一次。

## 脱敏诊断

反馈问题时可以提供：

- 浏览器与扩展版本；
- AnkiConnect 协议版本、目标牌组名和笔记类型字段列表；
- 管理页显示的状态、错误码和是否可重试；
- 问题发生在设置、释义、写入、音频、巡检还是备份阶段；
- 是否在本轮切换过 Anki profile、删除或手工修改过笔记。

不要提供 API Key、完整备份、浏览器存储、Cookie、私有原句或整个 Anki collection。公开状态 DTO 和正常错误详情不会包含 key、远端字段基线、noteId 或未确认写入内容。

## 先记住这六句话

1. **主动查词就是自动摘录。** 用户点一个词，或者对选中短语触发查词，立即持久化本次语境；释义就绪后自动写入本机 Anki。正常流程没有“加入 Anki”、确认释义、选择牌组等第二次操作。
2. 同一语言、相同词/短语、相同规范化语境和目标位置，重新打开同一记录；新语境自动产生新记录和新笔记。不是每次点击产生一条笔记，也不是一个词永远只有一条笔记。
3. 卡片采用“词语＋原句 → 释义＋原句”，默认一条笔记生成一张卡，不默认挖空、反向、输入答案。参考 LingQ 的公开示例，不宣称完整复刻其当前全部产品行为。
4. 插件负责摘录、内容更新、可靠写入、关联与差异状态。Anki 自己负责复习和 AnkiWeb 同步。**不调用 `sync`，不实现浏览器之间的队列同步，不根据复习进度改词汇熟悉度。**
5. 先保存本地，再请求 AI；保存流程不依赖弹窗存活。查词显示和制卡共享同一份语境释义，不各自调用一次模型。
6. 本期全部任务都是一期交付内容。中间验收点不是把一期缩成一个 addNote 演示。

## 执行顺序

先阅读 `SPEC.md`、`ARCHITECTURE.md`，再读 `TASKS.md`。从 `tasks/T00.md` 开始，按 T00～T21 顺序执行。一次只实施一个任务，不让多个 agent 同时修改遗留大文件。

每个任务：读相关接口 → 补失败测试 → 实现 → 运行本任务测试和已有回归 → 记录结果 → 独立提交。没有通过依赖任务的验收，不进入依赖它的任务。

接口边界问题以本包为准；不要自行创造第二套数据模型、第二个 Anki client、额外状态机框架或通用插件平台。

## 每次交付的证据

在 `PROGRESS.md` 记录任务状态、变更文件、测试命令、真实结果、提交号和未解决问题。区分“通过”“失败”“未运行”。Mock 测试通过不等于已通过真实 Anki 或 Firefox 验收。

对真实 Anki 的测试只使用专用测试牌组/笔记类型及本次测试创建的记录。不得清空 collection、修改用户复习计划、调用 AnkiWeb 同步或删除非测试笔记。

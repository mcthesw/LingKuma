## 修改范围

repository.js、独立 IndexedDB、数据库测试。

## 实施步骤

1. 建立 captures/jobs/media/meta stores、索引和显式 schema 迁移。与原词汇库和现有同步完全隔离。
2. createOrGetCapture 必须在并发查询下只有一条记录；capture+enrich job 原子提交。数据库事务完成才返回已保存。
3. 实现带 expectedRevision 的编辑、dirtyFields、generation递增、任务合并；任何网络/哈希计算必须在事务外。
4. 实现任务claim/有限租约/过期恢复/owner token校验；一个 capture+kind 只能有一个活动任务。
5. 实现保存pendingWrite、确认已核实字段、记录远端差异、分页读取等最小操作；写库失败/迁移失败不能删库补救。

## 必须验证

- A05：20个并发 create-or-get 只有一条记录/同类任务。
- A06：事务失败、quota失败、关闭连接、重启后恢复，未提交不得显示保存。
- A07：旧revision/旧lease无法覆盖新数据。

## 明确禁止

不以一个 storage.local 大数组读改写充当事务队列；不在 content script 内存词库。

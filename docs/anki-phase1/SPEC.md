# 一期产品规格：查词即摘录

## 1. 产品目标

在 LingKuma 现有阅读与查词流程中，提供一次主动查词即可完成的“语境解释 → 本地留存 → 本机 Anki 制卡”。正常使用只需要点词或完成原本的短语查词手势，不再有独立保存操作。

一阶段是可以日常使用的完整功能：包括设置、自动保存、可靠重试、内容修改、外部变更识别、摘录管理、数据备份和跨浏览器回归。不是复制整个 LingQ 产品，也不是一个 addNote 按钮。

## 2. 交互规则（强制）

### 2.1 一次性设置

用户提供运行中的 Anki 和 AnkiConnect。插件提供连接测试、目标牌组选择、专用笔记类型创建/验证、学习语言、释义语言、是否自动附加可用发音音频。

本期默认学习英语、释义中文；配置支持已有查词链路能明确提供的其他语言，不另外开发多语言词形学系统。语言身份来自本次查词/固定设置，不由 AI 的不稳定推断决定。

设置完成后自动摘录开启。可以全局暂停自动摘录；暂停时查词照常工作，界面显示暂停状态；它停止新的自动摘录，不删除历史，已经落盘的待处理任务仍继续。一次性设置可以需要用户操作，逐词保存不能需要额外操作。

未设置 Anki 时也保存主动查词到本地，明确显示“本地已保存，待配置 Anki”。首次配置完成后自动继续，不能要求逐条重新查词或逐条点保存。

### 2.2 什么触发自动摘录

- 网页中用户主动点击一个词并打开查词结果。
- 用户选中一个短语并触发现有查词手势/快捷键。开启即时划词查询的模式下，以最终选区确认并实际发起查询为事件，不以拖动中的 selectionchange 为事件。
- LingKuma 已有的 EPUB、PDF、字幕入口中，同样的主动查词事件。
- 已知词被用户主动查词也按同样规则处理；不因为“known”而拒绝保存。

不触发：悬浮预览、页面扫描/预取、整页翻译、拖动选区中间状态、打开历史记录、播放发音、点击编辑/关闭/词汇状态按钮、程序重绘弹窗。

**禁止在每个 DOM click 或每次 showTooltip 中无条件制卡。** 必须在“主动发起词/短语查询”这个语义入口捕获。原网页链接、输入框和编辑器交互不能被全局劫持。

### 2.3 首次查询

1. 同步取得目标词/短语、真实原句、所选位置、语言、来源。
2. 立即打开查词 UI；后台以一次事务保存记录与持久化任务。
3. 只有收到事务提交成功的响应后才显示“本地已保存”。
4. 自动获取当前语境释义；同一结果同时用于弹窗展示和 Anki 内容。
5. 得到有效释义后自动写入 Anki，并在核实写入后显示“已写入 Anki”。
6. 用户可以立刻继续阅读。关闭弹窗、切换查词对象或关闭标签页，不取消已经落盘的摘录和后续工作。

不出现制卡确认、词义选择、自动打开 Anki 添加窗口；不把查词改成一个填写卡片的表单。

### 2.4 重复查询与新语境

同一摘录身份再次查询：显示已保存的结果与状态，复用正在执行的任务，不重建笔记，不重复调用 AI，不因为重复点击而重置 CapturedAt。

同一词在不同语境中查询：自动建立新摘录并自动制卡。可以显示“此词已有其他摘录”，但不能让用户确认是否添加。

相同语境的判断以 ARCHITECTURE 的确定性身份为准，不使用词向量、AI 义项相似度或 lemma 合并。词条分组只是管理界面的视图，不影响制卡粒度。

### 2.5 异步返回

每次查词有独立 lookupSessionId；业务记录有独立 captureId。A 的请求在 B 的弹窗打开后完成，只能更新 A 的记录，不能把 A 的释义写进 B 的弹窗/笔记。

用户已手工改写内容时，迟到的 AI 结果不能覆盖修改。重新生成是显式可选操作，不在每次点击时发生。

## 3. 卡片形式

笔记类型：`LingKuma Lookup v1`。仅首次显式设置时创建，已有兼容类型复用。不在普通写入或插件启动时覆盖用户改过的模板/CSS。

默认一条笔记生成一张普通卡片：

正面：

> yields
>
> The iterator **yields** each matching record lazily.

背面：

> 产生、返回（一个值）
>
> The iterator **yields** each matching record lazily.
>
> 该迭代器按需逐个产生匹配的记录。
>
> 可选读音、发音按钮、简短用法说明、个人笔记、来源。

不默认挖空、不默认生成反向卡、不做选择题或听写。前后不需要附加“这里是什么意思”的题干。

这是本项目采用的“词语—释义，保留原句”模板。LingQ 官方公开教程展示过类似前后字段组合，也介绍了多种可配置复习活动；本规格不是对其当前默认 UI 或完整卡片系统的断言。出处见 `SOURCES.md` 的 R1。

### 3.1 专用字段

按下面次序创建，第一字段必须是不可变身份字段：

`CaptureId, Language, Term, Reading, Meaning, Context, SentenceTranslation, Usage, UserNote, Source, CapturedAt, Audio`

- CaptureId：纯 ASCII 的稳定 ID，不显示在卡片上。
- Language：本次学习对象的确定语言。
- Term：用户实际查询的词形/短语，不自动替换为原形。
- Reading：可选音标/读音，不要求模型猜测。
- Meaning：当前语境的简短释义，必填。
- Context：原句，只突出本次目标位置；不能用生成例句代替。
- SentenceTranslation：原句翻译，可选；失败不阻断已有有效释义的制卡。
- Usage：可选短说明，例如单词属于某个习语；不能偷偷把 Term 改成整个习语。
- UserNote：用户可编辑笔记。
- Source：安全渲染的来源标题、可用链接与定位说明；本地模型仍单独保存结构化来源。
- CapturedAt：首次摘录时间。
- Audio：完整的 `[sound:安全文件名]`，或空字符串。不能在模板中拼接 `[sound:{{filename}}]`。依据见 `SOURCES.md` 的 R8。

本期仅支持该专用类型及其兼容重命名，不做任意现有笔记类型的字段映射系统。缺字段、身份字段被移动、类型不兼容时暂停相关写入并给出修复说明，不删除重建用户笔记。

## 4. 材料与入口边界

单词、短语优先。普通网页完整支持。接入 LingKuma 已有的可选文本 EPUB、Mozilla PDF 阅读器、YouTube 字幕查询入口，不另做 PDF/OCR/视频转写/播放器。

- 优先使用原入口已有的真实句子和定位；其次取得包含所选词的真实文本片段。
- 无法取得整句时保存实际选中文本，并标注“上下文不完整”。不要要求手填才能继续，也不要伪造原句。
- 跨行、内联标签、同句同词多次出现，必须保存正确目标位置。
- PDF 保留可取得的页码；EPUB 保留可取得的章节/定位；字幕保留可取得的时间点。拿不到就留空，不猜。
- 点击单词不自动扩大为短语。模型识别到习语，可以在释义/说明中解释，但新的词组记录必须来自用户实际查询该词组。
- 整句/段落翻译仍使用原功能，默认不自动生成词汇笔记。目标文本上限作为保护性限制公开，不静默截断后制卡。

### 4.1 音频

一期包括“自动附加可取得的词/短语发音文件”。复用现有可下载/可返回音频字节的 TTS 或词典渠道，不能另要求订阅，不另写通用 TTS 平台。

若已配置可用的音频提供方，默认自动附加；播放能力不等于可下载能力，浏览器 speechSynthesis/chrome.tts 播放不能假冒成音频文件。至少验证一个真实可导出渠道；其余不支持的渠道显示“不可导出音频”。

文字先写入；音频完成后更新同一笔记的 Audio 字段。音频失败只影响音频，不能把整条文字摘录变为失败或要求用户重新查词。不截取视频原音轨，不做整句配音/图片生成/视频片段。

## 5. 本机写入与关联维护

插件只与本机 AnkiConnect 通信。负责本地队列、重试、创建和修改关联笔记、读取确认、外部修改/删除提示。使用 UI 文案“已写入本机 Anki”，不显示“已同步到手机/云端”。

AnkiWeb 同步、账户、合并、冲突、复习算法完全交给 Anki。生产代码不调用 sync、loadProfile、复习状态修改接口，不读取复习数据来修改 LingKuma 的词汇状态。

### 5.1 Anki 不在线

原句与查询意图仍本地落盘。已有有效释义正常显示；自动排队，Anki 恢复后自动继续。连接失败不能阻塞阅读，也不能为每条记录弹一次错误框。

### 5.2 AI 失败

保留原始摘录和任务，自动执行有界重试。没有有效释义时不创建空白/报错文案卡片；状态为“本地已保存，释义待完成”。可以集中重试或可选手工修正，但正常路径无需手动操作。

### 5.3 编辑、删除与冲突

- 在插件编辑内容：原地更新原 Anki 笔记；不删除再创建，不重置卡片或复习数据。
- Anki 端手工修改受管字段：检测到差异后保留两边版本、暂停该条写入。提供“保留 Anki 版本”“使用本地版本”或字段选择。这是异常处理，不是每次保存的确认。
- Anki 端删除已关联笔记：显示“Anki 笔记不存在”；不自动补建。可显式重建或停止管理。
- 重复点击缺失/冲突记录：仍打开原记录，不绕开状态偷偷新建。
- 插件的“停止管理此语境”：保留最小身份标记并停止未来自动写入；不删已有 Anki 笔记。再次查词仍可显示原记录；只有显式恢复才再管理。
- 本期不提供隐式双向删除，不将“已知词”变更解释为删除指令。

### 5.4 多桌面 B

每台浏览器各有本地摘录与队列，连接各自本机 Anki。Anki 已经把一条本项目笔记同步到另一台电脑时，该电脑查询相同 captureId 应关联已有笔记，而不是再建一条。

不复制浏览器队列、不远程连另一台 Anki、不强制触发同步。两台隔离的 Anki 在未同步前都创建相同记录，不承诺全局恰好一次；后来出现多个同 ID 笔记时停止自动更新并提示重复，不自动选一条覆盖或删除另一条。

## 6. 摘录管理与备份

提供独立轻量管理页：搜索词/短语、按词归组、按状态筛选、查看上下文和来源、编辑内容/个人笔记、查看关联笔记、处理异常、停止管理、备份与恢复。

备份不包含密钥、持久化中的锁、临时 requestId 或可直接重放的未确认写入。恢复先校验与重绑定，不能将旧备份当作“覆盖 Anki 当前状态”的命令。

## 7. 明确不做

不做词汇量测试、词频初始化、复习页/FSRS/SM2、Anki复习进度反向更新Known、多端队列复制、AnkiWeb同步代理、内容库、课程、OCR/转写、新阅读器、AI义项自动聚类、通用模板编辑器、全项目TypeScript/React迁移。

## 8. 成功标准

用户完成一次性设置后，只管读文章和点词。每一次主动查询要么产生可恢复的真实摘录并最终自动制卡，要么明确标为已存在/被排除/异常；不能悄悄丢失、串词、重复添加、伪造“已保存”或改动复习数据。
